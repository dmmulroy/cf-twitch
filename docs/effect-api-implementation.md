### Precision correction discovered during implementation

The original A01 recommendation was insufficient on its own: Effect DateTime truncates sub-millisecond fractions. A real transition probe accepted an earlier offline time `.1234Z` after a live start `.1235Z`. The implementation therefore retains a private exact fractional tie-break for equal milliseconds, including equality across trailing zeros. This is necessary domain representation handling, not a replacement timestamp schema or storage migration.

### Rejected SQL history pilot

The domain permits offsets beyond fourteen hours and arbitrary fractional precision. A local SQLite probe demonstrated:

- `julianday('2026-01-30T10:00:00+15:00')` and the `+23:59` variant return NULL, although both are valid `IsoTimestamp` values and Effect `DateTime.make` accepts them. A naive SQL conversion silently excludes those rows.
- SQLite rounds `.1235` to millisecond `.124`, while the selected Effect DateTime representation truncates it to `.123`.

Narrowing the public grammar, silently changing stored timestamps, or reading an unbounded history into memory to sort it is not an acceptable cleanup. A representation-preserving, native-compatible indexed design needs separate evidence. No claim is made that A01 fixes history SQL ordering.
